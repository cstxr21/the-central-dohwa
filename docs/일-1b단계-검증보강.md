> 🔒 **완료·배포 게이트 (모든 단계 md 공통 — 복붙 필수)**: 이 단계를 "완료"라고 말하기 전에, 이 문서의 `## 완료조건 (기계 판정)` 항목을 **마스터 `scripts/verify.mjs`로 실행**(`npm run verify`)해 **전부 PASS(GREEN)** 임을 출력으로 증명한다. 하나라도 FAIL·미구현·미측정·증거없음이면 **미완료** — "했다"고 말하지 말 것. auto 항목은 스크립트가 빌드결과·public·src를 읽어 검사, manual 항목은 `reports/manual-evidence.json`에 증거(수치·경로·요약)를 채워야 PASS. 마스터 verify 스크립트 원본·사용법은 **[11단계](일-11단계-배포점검.md) §마스터 검증 스크립트**에 있다. 신규 현장은 docs 프로세스 md 전체를 복붙 → 그 코드블록을 `scripts/verify.mjs`로 저장 → `content.ts`/`site.ts`만 그 현장 값으로 채우면 게이트가 자동으로 그 현장 기준 검사한다(라우트·슬러그 자동 감지). (현장 산출물 `이미지-배치표.md`는 복붙 대상 아님.)

> **작업 순서 1b/11 — 사실 검증·내용 보강** · 전제: [1a단계](일-1a단계-정보추출.md)(추출 원자료)
> **목적**: 1a가 뽑은 핵심 fact를 **공식 1차 출처와 1:1 대조·검증**하고, 미확정·누락을 외부 공식자료로 보강한다. "서사는 언론, 숫자는 1차 문서"로 출처를 가른다.
> **입력**: 1a 산출물(`pages`·`ocr.json`·`docs`(공식 PDF 포함)·`manifest.json`) · **산출물**: `factcheck.json`·`enriched.json`·`검증리포트.md`
> **다음 단계(2단계)로 넘길 것**: 확정 fact(라벨 일치/보강 완료). 미확정은 **"입주자모집공고 시점 기준 추후 안내"**(창작 금지).
> **배포 점검(11단계)**: "추후 안내"로 둔 미확정 fact·분양 법규 표기가 빌드 결과에 살아있는지는 배포 직전 **[11단계](일-11단계-배포점검.md)**가 회귀 점검한다(법규 표기 누락 = blocker).
> **적용**: 아래 ` ``` ` 프롬프트 블록을 AI에 전달. `<DOMAIN_NOTE>=분양`이면 ⑤ fact 목록·출처 사다리를 분양용으로 둔다(다른 도메인이면 [출처 사다리]만 갈아끼움). 이 파일은 자기완결.

# 사실 검증·보강 프롬프트 (범용 — ⑤⑥)

**핵심 원칙**: 하나의 출처로 다 하지 않는다. **콘텐츠 성격에 따라 출처를 가른다.**

| 콘텐츠 성격 | 주력 출처 | 라벨 |
|---|---|---|
| 카피·서사·입지스토리·시장맥락·분위기 | **언론**(다수 교차확인) | 보강 |
| 일반 fact(명칭·규모·주체 등) | **공식 1차 문서 + 1a가 받은 자료** | 검증 |
| 법정/핵심 수치(가격·일정·자격·비율·주체) | **1차 출처 문서(공고문·공시·사양서 등)** | 확정 |

> **왜**: 언론은 2차 출처라 보도자료 받아쓰기·반올림·오타가 매체 간 복제된다. 서사엔 최고지만 **숫자는 1차 문서로만 못박는다.** 1a가 ③에서 받은 공식 문서 PDF가 있으면 **그게 1순위 정본**(언론은 보조).
>
> **입력의 핵심 = OCR 이미지 텍스트**: 분양 원본은 콘텐츠가 이미지(CG)에 임베드돼 HTML `text.txt`는 면책 문구뿐인 경우가 많다. 따라서 **`ocr.json`(이미지 속 시설명·스펙·수치)이 HTML 텍스트보다 핵심 입력**이다. 둘을 합쳐 섹션별 fact를 도출하고 1차 출처로 검증한다. ⚠️ 1a에서 인포그래픽 패널이 OCR 누락됐으면 1b 전에 1a ④로 되돌아가 **전수 OCR부터 보강**(이미지 텍스트 없이는 정보 제약이 안 풀린다).
> **저장**: 섹션별 fact 검증 결과는 **산출물 `검증리포트.md`(extraction/)에 섹션별로** 기록하고, 확정 fact는 **`content.ts` 단일 소스**로. ⚠️ `docs/`나 페이지별 md에 현장 fact를 흩뿌리지 말 것(범용 docs·단일소스 원칙).

## 참고 (블록 밖 — 사람용)

### 왜 a/b로 나눴나
- **1a(추출)** 은 기계적·재현 가능(크롤·OCR) → 다음 현장에서 스크립트로 자동.
- **1b(검증·보강)** 은 판단·출처 추적(1차 문서 대조) → 사람+AI가 매 현장 직접.
- 관심사 분리로, 추출 원자료는 그대로 두고 검증만 다시 돌릴 수 있다(원자료 재크롤 불필요).

### 흔한 함정
- **언론으로 숫자 확정**: 보도자료 복제 오류가 매체 간 전파됨. 면적·일정·가격은 1차 문서로만.
- **공고문 미확보로 미확정 방치**: 정규청약 종료 단지는 공고문이 공개·아카이브된 경우가 많다 → 검색→직접 fetch로 끝까지 시도.
- **미확정을 슬쩍 채움**: 창작 금지. "입주자모집공고 시점 기준 추후 안내"로 남기고 리포트에 사유.

### 산출물이 2단계의 입력
- `factcheck.json`·`enriched.json`·`검증리포트.md`가 2단계 `content.ts`/`site.ts` **단일 소스의 입력**이 된다.
- 페이지별 md로 흩뿌리지 않는다(중복·드리프트 방지) — fact의 집은 코드(content.ts/site.ts) 하나.

## 완료조건 (기계 판정)

> 형식 `[Gxx-KEY] 설명 | auto|manual`. 마스터 `scripts/verify.mjs`가 이 `[Gxx-*]`를 파싱해 **구현·PASS를 강제**(이 문서에 ID를 선언했는데 스크립트에 검사가 없으면 = RED / 검사는 있는데 어느 md도 선언 안 하면 = 경고). **전부 GREEN 전엔 이 단계 "완료" 금지.**

- [G1B-FACT] 핵심 fact 일치/불일치/미확정 라벨 + 1차 출처 확보, 미확정='추후 안내' | manual
- [G1B-SINGLESRC] 현장 fact 단일소스 `content.ts` 존재(페이지 md에 raw 수치 분산 0) | auto

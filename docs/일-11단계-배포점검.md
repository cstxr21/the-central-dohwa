(현장 산출물 `이미지-배치표.md`는 복붙 대상 아님.)

```
당신은 배포 전 코드 정리 · 성능 · 배포 QA 감사관이다.
지금부터 "감사 모드"로 동작한다. 빌드된 Next.js 프로젝트를 점검하고
(a) 안전한 정리 patch (b) 삭제·개명 후보 목록 (c) 배포 준비 리포트만 출력하라.
파일·이미지 삭제나 일괄 개명을 임의로 실행하지 말 것 — 후보만 제시하고 사람 확인을 기다린다.

※ 이 블록에서 "9단계"는 같은 폴더의 SEO/GEO 문서(파일: 일-9단계-SEO-GEO.md)를 가리킨다.
   "9단계 [검증]", "9단계 [이미지 SEO]" 등은 그 파일 안의 해당 섹션을 뜻한다.

[전제 — 이 프로젝트의 스택]
- Next.js App Router + src/ 디렉토리, SSG(정적 생성) 우선, TypeScript, Tailwind CSS v4
- 이미지는 next/image, 모바일 우선 반응형
- 1~9단계로 페이지·디자인·콘텐츠·SEO 산출물(llms.txt/JSON-LD/robots/sitemap/메타/본문 fact)이 이미 적용된 상태

[이 문서의 범위 — 9단계와 겹치지 말 것]
- 이 문서가 본다: 코드/파일/이미지 정리 · 빌드 최적화 · 로딩속도 통과 게이트 · 배포 환경/보안 QA · 회귀 점검
- 이 문서가 안 본다(=9단계 소관): 검색 키워드·메타 카피·JSON-LD 설계·채널 전략·이미지 alt 내용·llms.txt 본문.
  · 단, "그 산출물이 빌드 결과에 살아있는가"(파일 200 응답·메타 존재 여부)는 회귀 점검으로 확인한다(아래 [6]).
  · 로딩속도·Core Web Vitals·이미지 포맷/치수 "측정 기준과 도구"는 9단계 [검증]·[이미지 SEO]·[채널별 가이드>구글]을 그대로 따른다. 여기서 수치를 새로 정의하지 말 것.

[중요도 — 배포 차단 vs 권장]
배포를 막는 것(blocker)과 있으면 좋은 것(권장)을 반드시 구분해 리포트하라.

  배포 차단(blocker) — 하나라도 걸리면 "배포 불가"로 표기
    1. next build 실패 또는 타입/ESLint 에러
    2. 프로덕션 번들에 비밀값 노출 (API 키·토큰·.env 값이 클라이언트 번들에 박힘)
    3. SSG여야 할 페이지가 fact를 CSR로만 렌더 → view-source에 본문 fact 없음 (9단계 핵심 전제 붕괴)
    4. /robots.txt · /sitemap.xml · /llms.txt 중 빌드 결과에서 누락되거나 비정상
    5. 콘솔 에러로 페이지가 깨지는 런타임 오류, 깨진 내부 링크(404)
    6. 관심고객등록 폼 미작동 또는 개인정보 동의 체크·처리방침 링크 누락
    7. 분양 법규 표기 누락 (광고심의필 번호·분양가 시점 표기·시행/시공 3주체) — 9단계 기준

  권장 — 개선하면 좋지만 배포는 가능
    빌드 경고 · 미사용 코드/의존성 · 번들 비대 · 미사용 이미지 자산 · console.log 잔존 등

[절대 보호 — 손대거나 지우지 말 것]
- HTML <title> (9단계 [HTML title 절대 불변]) — 변경·제안 금지
- 9단계가 만든 SEO 산출물(llms.txt/JSON-LD/robots/sitemap/메타/본문 fact 블록)의 내용 — 정리 대상 아님
- 기존 이미지 자산의 파일명·경로 — 캐시·외부참조(og·색인) 안정성 (9단계 [이미지 SEO])
  · "더 나은 키워드 파일명" 같은 개명 제안으로 기존 자산을 건드리지 말 것
- 동작 중인 본문 fact 텍스트·내부링크 구조 (9단계 [내부링크 최적화])
- 사용자가 의도적으로 둔 주석·설정 (불명확하면 지우지 말고 후보로만)

[점검 1 — 코드 정리] (대부분 권장, 안전한 것만 patch)
- 미사용 import · 미사용 변수/함수/컴포넌트 · 도달 불가(dead) 코드
- console.log / console.debug / debugger 잔존 (프로덕션 노출)
  · 에러 로깅(console.error)이나 의도된 로깅은 남길지 후보로 질문
- 주석 처리된 코드 블록 (살아있는 설명 주석은 보존, "죽은 코드 주석"만 후보)
- 임시/실험 파일 (예: *.test 흔적, 스크래치 컴포넌트, TODO 더미 페이지)
- 중복 유틸/스타일 (같은 일을 하는 함수·클래스 중복)
- any 남발·미사용 타입 (타입 에러는 blocker, 정리는 권장)
※ 자동 적용 가능한 안전 정리(미사용 import 제거 등)는 patch로, 판단이 필요한 건 후보 목록으로.

[점검 2 — 파일/이미지 정리] (★ 삭제는 실행 금지, 후보 목록만)
- 어디서도 import/참조되지 않는 컴포넌트·모듈·스타일 파일 → 후보 목록
- public/ 안에서 어떤 페이지·메타(og:image 포함)·CSS에서도 참조 안 되는 이미지/폰트/파일 → 후보 목록
  · 참조 추적은 코드·메타데이터·CSS url()·next/image src를 모두 훑어 판단
  · 확신이 없으면 "참조 불명 — 확인 필요"로 분류 (지우자고 단정하지 말 것)
- 중복 이미지(동일 이미지 다른 파일명) → 후보 목록 + 어느 쪽이 참조되는지 표기
- 미사용 npm 의존성(package.json에 있으나 코드에서 import 없음) → 후보 목록
- 빌드 산출 잔여물(.next 외 임시 빌드 폴더·소스맵의 프로덕션 노출 여부)
※ 각 후보에 "참조 0건 근거"를 1줄로 붙여라. 근거 없이 삭제 후보로 올리지 말 것.
※ 최종 삭제/개명은 사람이 확인 후 직접. AI는 목록 + 안전한 제거 patch 초안까지만.

[점검 3 — 빌드 최적화] (권장)
- 번들 사이즈: 비정상적으로 큰 청크·페이지 식별 (next build 출력 First Load JS 기준)
- 무거운 라이브러리가 초기 번들에 들어가 있으면 dynamic import / 코드 스플리팅 후보
- 이미지가 next/image로 처리되는지 (raw <img> 잔존 시 후보 — 단 SEO alt/치수는 9단계 소관)
- 폰트 최적화 (next/font 사용 여부, 불필요한 웹폰트 weight 로딩)
- Tailwind v4: 실제 사용되는 클래스만 번들되는지(미사용 커스텀 CSS·죽은 토큰)
- 'use client' 과다: fact를 담은 서버 컴포넌트가 불필요하게 클라이언트로 내려가면 후보
  (CSR로 인해 view-source fact가 사라지면 이건 권장이 아니라 [blocker 3])

[점검 4 — 로딩속도 게이트] (임계값·도구 기준은 9단계, ★측정은 여기서 반드시 실제로 실행)
- ★ "측정하면 됨"으로 적고 넘어가지 말 것 — 프로덕션 빌드(npm start)에 Lighthouse를 실제 실행해
  데스크탑(비스로틀)·모바일(시뮬레이션 느린4G) 둘 다 수치를 산출하고 (C) 리포트에 적는다.
  · 임계값은 9단계 [검증]의 Core Web Vitals 인용: LCP ≤ 2.5s · CLS ≤ 0.1 · INP(랩은 TBT 대체) 양호 · Perf 점수.
  · ★ 막는 건 "측정 누락"이지 "낮은 점수"가 아니다 — 실측값을 적었으면 통과. 수치 미달은 "성능 미달 플래그"
    (권장·다음 배포 개선)이지 배포 차단 아님(perf는 [중요도] blocker 7종에 없음). 측정 안 함 = 미통과.
  · 로컬 모바일 수치는 시뮬레이션 스로틀+콜드로 비관적 → 데스크탑 기준선과 함께 해석(데스크탑 양호면 실 CDN 모바일은 더 빠름).
- 흔한 원인 체크: 비최적 이미지·치수 미지정으로 인한 CLS·초기 JS 과다·블로킹 리소스·미사용 CSS·LCP 요소(히어로 priority)
  · 구체 수치·임계값은 9단계를 인용하고 여기서 재정의하지 말 것. 단정("이 정도면 빠르다") 금지 — 측정값으로만 판정.
  · 실행 예: npx lighthouse <url> --preset=desktop / --form-factor=mobile (헤드리스 Chrome 필요).

[점검 5 — 배포 환경/보안 QA] (일부 blocker)
- 환경변수: 클라이언트 노출용(NEXT_PUBLIC_*)과 서버 전용 분리 확인. 비밀값이 번들에 박히면 [blocker 2]
- .env / .env.local 이 저장소·배포물에 포함되지 않는지
- 콘솔/네트워크 에러 0, 깨진 링크·이미지 0 (깨진 링크는 [blocker 5])
- 404 페이지·리다이렉트·trailing slash 정책 일관성
- canonical/도메인 www 포함·제외가 9단계 결정과 일치하는지(불일치면 후보)
- 보안 헤더(가능 범위): HTTPS 강제, 기본 보안 헤더 적용 여부 (권장)
- favicon·앱 아이콘·기본 메타 누락 여부
- 분석 트래커(GA4/픽셀 등) ID가 placeholder가 아닌 실제 값인지(9단계 [단지 정보]와 대조)

[점검 6 — 회귀(regression) 점검] (9단계 [검증] 참조 — 반복 서술 금지)
- 정리/최적화 후 9단계 산출물이 살아있는지만 확인한다. 항목·방법은 9단계 [검증] 체크리스트를 그대로 사용:
  · view-source에 본문 fact가 정적으로 박혀있는가 (정리하다 SSG가 CSR로 바뀌지 않았는가)
  · /llms.txt · /robots.txt · /sitemap.xml 200 응답
  · 페이지별 title/og:title/description 길이·존재 (9단계 기준)
  · 내부링크 순환·orphan 없음
  · 본문 <a> 앵커에 비서술 텍스트("전체 보기·여기·more") 0 (9단계 [내부링크] 자연어+키워드 앵커) — Lighthouse SEO `link-text`로 교차 확인. 단, 버튼·라이트박스 트리거 라벨은 형제 서술 텍스트가 있으면 예외.
- 9단계 [검증]을 여기 복붙하지 말고 "9단계 [검증] 수행"으로 지시하고, 정리로 인해 깨진 항목만 리포트.

[점검 7 — 배포 직전 최종 확인 (분양 특화)] (일부 blocker · 간단히)
- 관심고객등록 폼 (9단계가 안 보는 기능 — 여기서 확인):
  · 제출이 실제 동작하고 데이터가 목적지(메일/시트/DB 등)에 도달하는가
  · 필수값 검증·에러 표시가 동작하는가
  · 개인정보 동의 체크박스 + 처리방침 페이지 링크가 살아있는가 ([blocker 6])
- 분양 법규 표기 회귀 (내용 기준은 9단계 [어뷰징·법적 가드레일] — 여기선 "살아있나"만, [blocker 7]):
  · 광고심의필 번호 · 분양가/일정 시점 표기("○○ 입주자모집공고 기준") · 시행/시공 3주체
- 실기기·도메인 (육안):

## 기계 검증 게이트 (배포·"완료" 선언 전 필수 실행 — 결정론적)

> ⚠️ **이 게이트를 통과하기 전엔 "완료/배포 가능"이라고 말하지 말 것.** 눈으로 보지 말고 **빌드 후 아래를 실제 실행**해 0/누락을 기계로 확인한다. (이번 현장에서 desc 83자·입지 JSON-LD 누락·sales 이미지 누락이 "끝났다" 선언 뒤에야 발견된 재발 방지.) `scripts/verify.mjs`로 묶어 1커맨드화 권장.

`npm run build` 성공 후, `.next/server/app/*.html`와 `public/`을 대상으로 다음을 검사해 **모두 0/통과**여야 한다:

1. **빌드/타입/린트**: `next build` 성공 + **`npx eslint src` 에러·경고 0**(미사용 import·변수·dead code·불필요 eslint-disable 포함 — 빌드만으론 경고가 안 잡힘, eslint 별도 실행).
2. **산출물 6종 존재**: `robots.txt`·`sitemap.xml`·`llms.txt`(+`rss.xml` 있으면) 빌드 결과/`public`에 존재. sitemap `<loc>` 수 = 라우트 수.
3. **페이지별 메타 길이/구분**: 전 라우트 HTML에서 `description` **≤80자**, `og:title` **≤40자**, `og:title ≠ <title>`, `canonical` 존재(자기 경로).
4. **JSON-LD 매핑 1:1**: 아래 페이지에 `application/ld+json` + 올바른 `@type`이 박혔는지 — home·사업개요·입지·단지·평면도 = `Residence`, 분양안내 = `Residence`+`AggregateOffer`(또는 Offer), 모델하우스 = `LocalBusiness`/`RealEstateAgent`(주소 공개 시), `/faq` = `FAQPage`, `/news/[slug]` = `NewsArticle`. **대상 페이지에 누락 0.**
5. **OG 이미지 실존**: 모든 `og:image` URL → `public` 파일 실존(404 0), 1200×630. 페이지 주제별 매핑 적용.
6. **이미지 참조 404 0**: 코드의 모든 `/images/**.webp` 참조 파일이 실존.
7. **내부링크 전환 동선**: 모든 콘텐츠 페이지 본문 링크 **2종+**, **orphan 0**(news/faq 포함), 분양안내·관심고객등록 inbound 다수, 퍼널(입지→평면도→분양→모델하우스→등록) 완주.
8. **플레이스홀더/창작 0**: `{현장명}`·`{…}`·`TODO`·`placeholder`·`준비중`(미공개 placeholder 제외) 잔존 0. 미확정 항목은 "입주자모집공고 기준 추후 안내".
9. **표시광고·프레이밍 가드(분양 특화)**:
   - 분양가·일정에 시점 표기("입주자모집공고 기준") 동반, "최저가/확정/완판" 단정 0.
   - **미분양 인식 표현 0**: 청약 종료 시 "지난 청약 일정(종료) 표·잔여세대·소진에 따라 변동" 노출 금지 → "선착순 분양 중"으로.
   - **없는 기능 표기 0**: 실제 자산 없는 "E-모델하우스/360° VR" 등 문구 금지.
   - 시행/시공(가능 시 신탁) 3주체 표기.
10. **영역 적합성·near-dup 0**: 페이지별 섹션→콘텐츠 매핑([6단계](일-6단계-서브-단지정보.md)) 준수, 동일 이미지/카피 블록을 두 페이지에 중복 게재 0(허브=메인 teaser 제외).
11. **이미지 최대 활용**: 각 페이지 섹션 category keep 이미지 미사용 0(또는 사유 명시), 세로 인포그래픽 무크롭.
12. **미사용 자산·코드 0(실제 제거)**: `public/images`·`public/videos`에서 코드·메타(og 포함)·CSS 어디서도 참조 안 되는 파일을 **사람 승인 후 실제 제거**(후보만 내고 방치 금지 — 미배포면 지금). 미사용 import·변수·dead code도 제거(위 #1 eslint 0과 연동). ⚠️ `extraction/`·`docs/`는 배포 자산 아님 = **제거 대상 제외**. 참조 추적은 리터럴+템플릿(`prefix-${n}`)+`Array.from`+og+영상까지. ⚠️ 미사용 스캔은 **빌드 결과(.next)에 전개된 최종 경로**를 ground truth로 쓸 것(소스만 grep하면 템플릿 `prefix-${n}` 전개분을 미사용으로 **오탐**). next/image 최적화 경로(`%2Fimages` 인코딩)도 basename은 그대로라 basename 매칭으로 커버.
13. **로딩속도 실측(필수 — "측정함"을 증명)**: ⚠️ **"9단계 도구로 측정"이라고 적어두고 실제로 안 돌리는 것을 금지**(이번 현장에서 "로딩속도 최적화 점검했다"고 선언했다가 실측 미실행이 들통난 재발 방지). 프로덕션 빌드(`npm start`)에 **Lighthouse를 실제 실행**해 수치를 산출한다. 임계값은 9단계 [검증](구글 Core Web Vitals)을 단일 출처로 인용: **LCP ≤ 2.5s · CLS ≤ 0.1 · INP(랩은 TBT로 대체) 양호 · Perf 점수 기록**.
    · **데스크탑(비스로틀)과 모바일(시뮬레이션 느린4G) 둘 다** 산출하고 **둘 다 리포트에 적는다**. 로컬호스트 모바일 수치는 시뮬레이션 스로틀+콜드+CPU경합으로 **비관적**이므로, 데스크탑 기준선과 함께 해석한다(데스크탑 LCP가 양호하면 실제 CDN 모바일은 로컬 모바일보다 빠름). **실측값을 적지 않은 리포트는 #13 미통과**.
    · ⚠️ **이 게이트가 막는 건 "측정 누락"이지 "낮은 점수"가 아니다.** 실측값을 리포트에 적었으면 #13은 통과 — 수치가 임계값 미달이어도 그건 [점검 4]대로 "성능 미달 **플래그**"(권장·다음 배포 개선 대상)이지 배포 차단(blocker)이 아니다(perf는 [중요도] blocker 7종에 없음). 즉 **측정 안 함 = #13 미통과 / 측정함+수치미달 = 통과+플래그**.
    · CLS>0면 이미지 width/height 누락 의심(#11/이미지 SEO), Perf 급락이면 LCP 요소(히어로 priority 여부)·미사용 CSS·초기 JS를 점검. 단정("이 정도면 빠르다") 금지 — **측정값으로만** 판정.
    · 실행 예: `npx lighthouse <url> --preset=desktop` / `--form-factor=mobile`(Chrome 경로는 Playwright chromium 재사용 가능). 결과 JSON에서 `categories.performance.score`·`audits.largest-contentful-paint`·`cumulative-layout-shift` 추출.
14. **링크 텍스트 서술성(SEO)**: 본문 `<a>` 앵커에 "전체 보기·여기·more" 등 **비서술 텍스트 0**(9단계 [내부링크] 자연어+키워드 앵커). Lighthouse SEO `link-text` 감사로 교차 확인. (버튼·라이트박스 트리거의 라벨은 형제 서술 텍스트가 있으면 예외.)

## 참고 (블록 밖 — 사람용)

- **이 단계는 "정리·빌드·배포 QA 게이트"다.** 검색 최적화 자체(키워드·메타 카피·JSON-LD·채널 전략)는 [9단계](일-9단계-SEO-GEO.md)가 원천이고, 여기서는 9단계 산출물이 **빌드 결과에 살아있는지**와 **불필요한 것의 정리**만 본다. 9단계와 내용이 겹치면 그건 이 문서의 실패다 — 항상 9단계를 참조로 가리킬 것.

- **삭제는 사람이 한다.** AI는 "참조 0건 근거"가 붙은 후보 목록까지만 낸다. 메모리 규칙(원본 파일을 지시 없이 삭제·개명 금지) + 9단계 [이미지 SEO](기존 자산 강제 개명 금지)와 일치. 후보 중 "참조 불명"은 반드시 직접 확인 후 처리.

- **blocker 7가지만 외워두면 된다**: ① 빌드/타입 에러 ② 비밀값 번들 노출 ③ fact가 CSR로만(view-source 비어있음) ④ robots/sitemap/llms 누락 ⑤ 깨진 링크·런타임 오류 ⑥ 관심고객등록 폼 미작동·동의/처리방침 누락 ⑦ 분양 법규 표기 누락. 이 일곱은 배포 중단 사유. 나머지(미사용 코드·번들 크기·console.log)는 권장이라 다음 배포로 미뤄도 됨.
  · ⑥·⑦은 분양 특화 — ⑥ 폼은 사이트 존재 목적(리드 수집)이라, ⑦ 법규는 누락이 실제 법 위반이라 차단. 법규 "내용"은 9단계가 원천, 여기선 "빌드에 살아있나"만 본다.

- **로딩속도 임계값은 9단계에서 가져오되, 측정은 11단계가 실제로 돌린다.** 임계값(LCP≤2.5s·CLS≤0.1·INP≤200ms)은 9단계 [검증] 단일 출처. 단 **측정 행위 자체는 기계 게이트 #13의 의무** — Lighthouse를 실제 실행해 데스크탑+모바일 수치를 (C) 리포트에 적는다. "9단계 도구로 측정하면 됨"이라고만 적고 안 돌리는 것 = #13 미통과(과거 실수). 배포 URL이 생기면 PageSpeed Insights로 한 번 더 확인(필드데이터).

- **재배포마다 가볍게 반복**: 1회성 게이트지만, 분양가·일정 변경으로 재배포할 때 (B)·(C)만 빠르게 다시 돌리면 회귀를 잡을 수 있다. 10단계(블로그 발행) 후 재배포에도 동일 적용 가능.

- **현장 무관 재사용**: 이 파일은 placeholder가 거의 없어 다른 일반분양 현장에도 그대로 복사해 쓸 수 있다.

- **마무리 확인**:
  - [ ] **기계 검증 게이트 14항 전부 통과**(빌드 후 실행 — 메타길이·JSON-LD매핑·OG/이미지 404·orphan·플레이스홀더·표시광고/미분양/VR 가드 = 0/통과)
  - [ ] **#13 로딩속도 실측값**(Lighthouse 데스크탑+모바일 Perf·LCP·CLS)이 (C) 리포트에 기록됐는지
  - [ ] **#14 비서술 링크 0**(Lighthouse SEO link-text)
  - [ ] (C) 배포 리포트 1줄 판정 = "배포 가능"인지 확인(blocker 0)

- **SEO "본질"(키워드·메타 카피·랭킹)은 11단계가 점검하지 않는다 — 9단계 소관.** 11단계는 "9단계 산출물이 빌드에 살아있나 + 정리·속도"만 본다. 따라서 "네이버/구글/다음 SEO·검색 키워드 최상단·AI 유입 최적화가 됐나"라는 질문에 11단계만으로 "다 했다"고 답하면 **범위 혼동**이다. ① 산출물 생존·메타 길이·JSON-LD·내부링크·어뷰징 가드 = 11단계 기계 게이트가 커버 ② 키워드 선정·카피 적절성 = 9단계 감사 ③ **실제 랭킹/최상단 = 배포 후 검색엔진이 정함(사전 점검 불가)**. 셋을 구분해 답할 것.

## 완료조건 (기계 판정)

> 형식 `[Gxx-KEY] 설명 | auto|manual`. 마스터 `scripts/verify.mjs`가 이 `[Gxx-*]`를 파싱해 **구현·PASS를 강제**(이 문서에 ID를 선언했는데 스크립트에 검사가 없으면 = RED / 검사는 있는데 어느 md도 선언 안 하면 = 경고). **전부 GREEN 전엔 이 단계 "완료" 금지.**

- [G11-ESLINT] `npx eslint src` 에러·경고 0 | auto
- [G11-UNUSED] public 미사용 이미지/영상 0(빌드결과 ground-truth) | auto
- [G11-PERF] reports/lighthouse.json에 데스크탑+모바일 실측(Perf·LCP·CLS) 기록 | auto
- [G11-SECRET] 클라이언트 번들(.next/static)에 비밀값(텔레그램 토큰 등) 0 | auto
- [G11-DEVICE] 실모바일 기기로 메인+핵심 페이지 깨짐 0 육안 | manual

//  (1) 평면: EVI["G3-READABLE"] = "증거 문자열"
//  (2) 중첩(실제 산출 형식): EVI["STAGE-3"].manualGates["G3-READABLE"] = "..." / 게이트id가 top-level 객체 키(EVI["G1A-EXTRACT"]={status,summary,evidence})
function manualEvidence(id) {
  const asStr = (x) => (typeof x === "string" && x.trim() ? x.trim() : "");
  if (asStr(EVI[id])) return asStr(EVI[id]);
  const direct = EVI[id];
  if (direct && typeof direct === "object") {
    if (/pass/i.test(direct.status || "") || asStr(direct.summary) || (direct.evidence && Object.keys(direct.evidence).length))
      return asStr(direct.summary) || `status=${direct.status || "?"}`;
  }
  for (const v of Object.values(EVI)) {
    if (v && typeof v === "object")
      for (const bucket of [v.manualGates, v.autoGates, v.gates])
        if (bucket && asStr(bucket[id])) return asStr(bucket[id]);
  }
  return "";
}

function orphanCheck() {
  const inbound = {};
  CONTENT_ROUTES.filter((r) => r !== "index").forEach((r) => (inbound[r] = 0));
  for (const r of ROUTES) {
    for (const m of html(r).matchAll(/href="\/([\w-]+)(?:[/#][^"]*)?"/g)) {
      const t = m[1]; if (t in inbound && t !== r) inbound[t]++;

  }

  return { pass: orphans.length === 0, ev: orphans.length ? `orphan: ${orphans}` : `orphan 0(홈 제외 전 라우트 inbound 1+)` };
